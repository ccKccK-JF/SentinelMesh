# 自适应调度状态机

## 目标

调度不能直接追随单个采样值，否则短暂尖峰会导致节点权重来回跳变。状态机把“指标评分”和“是否允许承载新流量”分开：先平滑普通波动，硬故障立即生效，再通过连续样本和时间冷却控制恢复。

## EWMA

每个节点、每个评分指标独立保存指数移动平均：

```text
smoothed(t) = alpha * current(t) + (1 - alpha) * smoothed(t-1)
```

默认`alpha=0.35`。首个样本直接作为初值。CPU、内存、Load和磁盘利用率参与平滑；原始指标仍保存在节点快照中，便于排查。

## 硬门槛

硬门槛读取原始值，不读取EWMA：

| 指标 | 默认门槛 |
|---|---:|
| CPU利用率 | 99.5% |
| 内存利用率 | 98% |
| 磁盘利用率 | 99.5% |

任一门槛命中后，节点立即标记为unhealthy，健康分设为5，并从最后一次命中开始重新计算30秒恢复冷却；路由策略同步将其权重降为0。

## 滞回

普通评分状态使用两个连续样本门槛：

- 恶化：连续2个目标状态相同的样本后迁移；
- 改善：连续3个目标状态相同的样本后迁移；
- 候选状态变化会重新计数，避免把不连续样本拼接成一次迁移。

健康分默认边界为：`healthy >= 70`、`degraded >= 40`、其余为`unhealthy`。HTTP快照中的`health_changed_at`记录最后一次实际状态迁移；滞回保持期间`health_reason`会显示候选状态和计数。

## 恢复冷却

节点进入unhealthy后设置`recovery_not_before`。冷却截止前，即使评分恢复也不会累计改善样本；截止后才开始连续3次改善确认。成功离开unhealthy后清空恢复截止时间。

## 生命周期

状态按`node_id`隔离。当同一节点使用新的Boot ID注册时，控制面会清空：

- EWMA历史；
- 当前滞回候选和计数；
- unhealthy恢复冷却。

这样可以避免机器重启后继续继承上一个启动周期的异常状态，同时仍保留同一Boot ID断线重连的序列号和健康状态。

## 路由权重

控制面把所有节点转换为总和固定为10,000的整数权重：

1. 断连、unknown和unhealthy节点不可路由，权重为0；
2. healthy节点使用健康分作为原始权重；
3. degraded节点的原始权重乘以0.5；
4. 从unhealthy恢复的节点以10%系数开始，在60秒内线性增加到100%；
5. 使用最大余数法取整，保证最终整数权重严格等于10,000。

`GET /v1/routing`返回`version`、`generated_at`及各节点的权重、资格、状态和原因。节点连接、健康状态、权重或恢复阶段变化时版本递增。HTTP `ETag`等于快照版本，支持`If-None-Match`条件轮询和304响应。

## 假网关

`cmd/fake-gateway`读取路由快照并使用平滑加权轮询分配请求。该算法不会生成随机抖动，在完整权重周期内分配数量与权重精确一致。若没有可用节点，网关显式失败，不会回退到unhealthy节点。

验证命令：

```bash
./scripts/test-routing.sh
```
